Beschrijving

Zorg dat de OpenAPI specificatiedocumenten van de Edu-V API’s beschikbaar worden gesteld in een vrij toegankelijke Git repository en maak het adres hiervan bekend.

Adviseer ontwikkelaars om deze repository als submodule op te nemen in de eigen repositories en code generators te gebruiken om responses volgens de juiste schema’s te genereren.

Overweeg het gebruik van Git tags om releasedata en/of versienummers van specifieke API’s aan te duiden:
De toestand van alle API’s tezamen zou met een tag op basis van datum aangeduid kunnen worden, bijvoorbeeld 2024-09-27
De huidige versie van de students API zou met de tag students-0.9.1 aangeduid kunnen worden

Onderbouwing van nut of noodzaak

Fouttolerantie, integreerbaarheid, bruikbaarheid: tijdens implementatie en onderhoud van Edu-V API’s is het belangrijk om de specificatie zo getrouw mogelijk te volgen. Door deze wijziging door te voeren, kunnen de Edu-V OpenAPI schema’s geautomatiseerd met hulp van een codegenerator omgezet worden naar programmacode.

Onderhoudbaarheid: wanneer er wijzigingen of uitbreidingen plaatsvinden in de OpenAPI schemas, kunnen ontwikkelaars de nieuwe versie integreren met hulp van Git tooling, en valideren dat de nieuwe versie correcte en verwachte wijzigingen bevat.

Transparantie: verbeterd historisch inzicht in hoe de specificaties zich hebben ontwikkeld.

Samenwerking: het adopteren van Git voor onderhoud van OpenAPI specs maakt het ook mogelijk om voor kleinere aanpassingen van de Pull Request workflow gebruik te maken, zodat er een lichtere variant van het RFC-proces ontstaat.

Modulariteit, hergebruik: wanneer OpenAPI specs gezamenlijk in een Git repository gehost worden, kunnen er over de API’s heen gedeelde types gedefinieerd worden, zoals bv. voor het attribuut status van het object StatusResponse, dat nu een integer is, zonder beperking op de geldige waarden.
