Beschrijving

In het conceptueel model voor Verwerven en in gebruik nemen leermiddelen is de referentiecomponent Bestelomgeving leermiddelen uitgewerkt met diverse gegevensdiensten. De referentiecomponent draagt zorg voor het realiseren van UC4: Bestellen leermiddelen door een Besteller. Daarnaast is er een gegevensdienst Leermiddelorders ingetekend om bij een Ordersysteem leermiddelen van een Leermiddelenaanbieder leermiddelen in te kopen. In de praktijk zijn dit echter compleet gescheiden processen. Het verkopen van leermiddelen is een order-to-cash proces en het inkopen van leermiddelen is een purchase-to-pay proces. Het voorstel is om deze scheiding in functionaliteit scherper aan te brengen door de definitie van Bestelomgeving leermiddelen en Ordersysteem leermiddelen aan te passen.

Onderbouwing van nut of noodzaak

Dit wijzigingsverzoek leidt tot een betere scheiding van verantwoordelijkheiden tussen de referentiecomponenten en maakt ook meerdere implementatiescenario's mogelijk. We lichten twee varianten toe.

Verkoop via een distributeur In het traditionele model van verkopen via een distributeur, koopt een distributeur leermiddelen in en verkoopt deze vervolgens door aan scholen of particulieren. Een distributeur beschikt voor dit proces over een ERP systeem waarbij leermiddelen worden ingekocht (purchase-to-pay) en orders uit een shop (Bestelomgeving leermiddelen) worden verwerkt. Er is hier sprake van een inkooporder (PurchaseOrder) en een verkooporder (SalesOrder). De inkooporder leidt tot een factuur vanuit de uitgever die betaald moet worden. De verkooporder leidt tot een factuur die verzonden wordt naar de school en betaling ontvangen wordt.

Directe verkoop aan schoolbesturen In het voortgezet onderwijs zijn er steeds meer schoolbesturen die met behulp van inkoop- en licentietools administratieve ondersteuning krijgen bij het inkopen van leermiddelen bij verschillende uitgevers. In dit scenario is er geen sprake van een traditionele relatie tussen leermiddelenverkoper en leermiddelenaanbieder (of distributeur en uitgever). Het schoolbestuur koopt rechtstreeks in bij de uitgever. De uitgever verwerkt de bestelling, levert deze conform de afgesproken voorwaarden (op school of bij een fulfilmentpartner) en stuurt de factuur naar het schoolbestuur (of naar de school). In dit scenario is er sprake van een inkooporder door het schoolbestuur. Immers het schoolbestuur ontvangt een factuur van de uitgever voor de bestelling.

We stellen voor om de referentiecomponenten als volgt te definieren:

De inkooporder volgt uit een regulier purchase-to-pay proces en leidt tot een inkomende factuur.Catalogue API (afnemer) en Order API (verzender)Ordersysteem leermiddelenEen applicatie die een order kan verwerken, de levering kan initieren en zorg kan dragen voor facturatie naar de klant. We stellen voor om de Bestelomgeving leermiddelen omwille van de duidelijkheid te schrappen. Dit betreft enkel een UI waar een school of particulier een bestelling kan plaatsen. Afhankelijk van de toepassing kan dit een UI zijn op het ordersysteem leermiddelen van een uitgever (webshop uitgever), het ordersysteem leermiddelen van een distributeur (webshop distributeur) of de inkoopomgeving leermiddelen van een softwareleverancier (inkoop- en licentietool).

Bovenstaande wijziging maakt de volgende scenario's mogelijk:

** 1. School bestelt bij uitgever**

  1. School plaatst inkooporder bij Uitgever. School kan gebruik maken van inkoopomgeving om order via Order API te plaatsen.

  2. Uitgever verwerkt order en levert uit.

  3. School ontvangt bevestiging van levering.

  4. Uitgever factureert aan school.

** 2. School bestelt bij distributeur** Inkoop door distributeur:

  1. Distributeur plaatst inkooporder bij Uitgever. Distributeur maakt gebruikt van inkoopomgeving om order via Order API te plaatsen.

  2. Uitgever verwerkt order en levert uit.

  3. Distributeur ontvangt bevestiging van levering.

  4. Uitgever factureert aan distributeur.

Verkoop door distributeur:

  1. School plaatst inkooporder bij Distributeur. School kan gebruik maken van inkoopomgeving om order via Order API te plaatsen.

  2. Distributeur verwerkt order en levert uit. Bij uitlevering wordt allocatie voor school gemaakt en gedeeld met uitgever.

  3. School ontvangt bevestiging van levering.

  4. Distributeur factureert aan school.
