Beschrijving

De huidige specificatie biedt onvoldoende informatie om de volgende use cases te ondersteunen:

"1. Als leermiddeleninkoper heb ik behoefte aan inzicht in het saldo ingekochte digitale leermiddelen minus gealloceerde digitale leermiddelen opdat ik weet hoeveel digitale leermiddelen ik nog kan alloceren aan scholen of particulieren."

"2. Als licentiedistributeur heb ik behoefte aan inzicht in het saldo gealloceerde digitale leermiddelen minus toegekende aanspraken opdat ik weet hoeveel digitale leermiddelen ik nog kan toekennen aan gebruikers."

Onderbouwing van nut of noodzaak

Een organisatie die de combinatie van de Order API en de Delivery API/Entitlement API gebruikt heeft op dit moment geen manier om te achterhalen welke saldo's er nog voor hem beschikbaar zijn om enerzijds te alloceren en anderzijds toe te kennen aan gebruikers.

De meest natuurlijke plek voor deze informatie in het huidige stelsel is de Usage API die aangeboden wordt door de Licentieregistratie. in de Licentieregistratie wordt immers DeliveryOrderUsage gedeeld waarbij subtotalen zijn toegevoegd van aanspraken in een bepaalde status, bijvoorbeeld totalEntitled, totalLicensed, etc. Kortom, via de Usage API worden deze quantities reeds gedeeld.

Dit voorstel betreft een herziening van de Usage API om te voldoen aan de bovenstaande use cases en de huidige use case van het delen van de status van een Entitlement te behouden:

"3. Als licentiedistributeur heb ik behoefte aan inzicht in de status en het gebruik van een aanspraak."

Voor de drie use cases zouden we graag ook drie separate Usage objecten definieren:

1. ProductStatistics

Dit object bevat een array met aantallen voor de betreffende productId. Hierin is de volgende informatie opgenomen:

  • productId: het productnummer (EAN) van het product.

  • contractId: optioneel contractnummer waarbinnen de inkooporders, allocaties en aanspraken vallen.

  • activationUntilDate: de uiterlijke datum tot wanneer de aanspraken in gebruik genomen kunnen worden. Deze datum geeft ook de 'houdbaarheid' van het tegoed aan.

  • totalFulfilled: totaal aantal fulfilled uit de inkooporders voor het product.

  • totalAllocated: totaal aantal gealloceerd in DeliveryOrders. Betreft een aggregatie van de DeliveryOrderStatistics voor hetzelfde productId, de activationUntilDate en het contractId.

  • balanceToAllocate: dit betreft het saldo totalFulfilled minus totalAllocated. Dit kan een positief of negatief aantal zijn. Bij een positief aantal is er nog ruimte om DeliverOrders te verwerken. Bij een negatief aantal dient er een Inkooporder geplaatst te worden om het tegoed op te hogen.

  • totalEntitled: totaal aantal entitlements op de allocaties met de status entitled. Dit aantal kan geannuleerd worden.

  • totalLicensed: totaal aantal entitlements op de allocaties met de status licensed.

  • totalBocked: totaal aantal entitlements op de allocaties met de status blocked. Dit aantal kan gedeblokkeerd worden.

  • totalCancelled: totaal aantal entitlements op de allocaties met de status cancelled. Dit aantal is reeds geannuleerd.

  • totalExpired: totaal aantal entitlements op de allocaties met de status expired. De gebruikersperiode is afgelopen.

  • balanceToEntitle: dit betreft het saldo geaggregeerd over alle allocaties, zijnde totalAllocated minus totalEntitled minus totalLicensed minus totalLicensed minus totalExpired en (optioneel) minus totalBlocked (Bij 'concurrent licensing' wordt dit aantal niet meegerekend. Het gaat dan enkel om de entitlements die in gebruik zijn).

Dit object kan gedeeld worden via twee endpoints: GET /statistics/products --> Alle ProductStatistics objecten. Optioneel te filteren met query parameters contractId en activationUntilDate. GET /statistics/products/{productId} --> Alle ProductStatistics objecten voor een specifiek productId. Optioneel te filteren met query parameters contractId en activationUntilDate.

2. DeliveryOrderStatistics

Dit object bevat vergelijkbare informatie maar dan alleen in relatie tot één DeliveryOrder.

  • deliveryOrderId: de id van de DeliveryOrder.

  • productId: het productnummer (EAN) van het product.

  • contractId: optioneel contractnummer waarbinnen de inkooporders, allocaties en aanspraken vallen.

  • school: optioneel veld indien de DeliveryOrder voor een school is.

  • activationUntilDate: de uiterlijke datum tot wanneer de aanspraken in gebruik genomen kunnen worden. Deze datum geeft ook de 'houdbaarheid' van het tegoed aan.

  • totalAllocated: betreft de quantity uit de DeliveryOrder.

  • totalEntitled: totaal aantal entitlements op de allocatie met de status entitled. Dit aantal kan geannuleerd worden.

  • totalLicensed: totaal aantal entitlements op de allocatie met de status licensed.

  • totalBocked: totaal aantal entitlements op de allocatie met de status blocked. Dit aantal kan gedeblokkeerd worden.

  • totalCancelled: totaal aantal entitlements op de allocatie met de status cancelled. Dit aantal is reeds geannuleerd.

  • totalExpired: totaal aantal entitlements op de allocatie met de status expired. De gebruikersperiode is afgelopen.

  • balanceToEntitle: dit betreft het saldo op de allocaties, zijnde totalAllocated minus totalEntitled minus totalLicensed minus totalLicensed minus totalExpired en (optioneel) minus totalBlocked (Bij 'concurrent licensing' wordt dit aantal niet meegerekend. Het gaat dan enkel om de entitlements die in gebruik zijn).

Let op! Het voorstel is om de array entitlements uit dit object te verwijderen. Het is niet zinvol om al deze informatie standaard terug te geven als onderdeel van dit object. Daarbij is dit niet RESTful. Zie EntitlementUsage voor nieuw voorstel.

Dit object kan gedeeld worden via twee endpoints: GET /statistics/deliverorders --> Alle DeliveryOrderStatistics objecten. Optioneel te filteren met query parameters productId, contractId, school en activationUntilDate. GET /statistics/deliverorders/{id} --> Alle DeliveryOrderStatistics objecten voor een specifiek productId. Optioneel te filteren met query parameters productId, contractId en activationUntilDate.

3. EntitlementUsage

Dit betreft het huidige object EntitlementUsage. Hier hoeft niets aan te veranderen. Wel zouden we de endpoints willen herzien: GET /usage/entitlements --> Alle EntitlementUsage objecten. Optioneel te filteren met query parameters productId, contractId, school en activationUntilDate GET /usage/entitlements/{id}--> Opvragen van een enkel EntitlementUsage object.

Met deze endpoints kunnen de bestaande endpoints /usage/contracts/{id} en /usage/school te komen vervangen. Deze zijn vervangen door query parameters op respectievelijk de DeliveryOrderStatistics of het EntitlementUsage object.

Tot slot, stellen we voor om het endpoint POST /usage/school/user te verwijderen. Dit endpoint heeft geen functionele waarde. Een partij die informatie over een gebruiker wil dient deze op te vragen bij de aanspraakmanager. Hier kunnen alle entitlements opgevraagd worden. Vervolgens kan in de Usage API de gebruiksgegevens opgevraagd worden middels de verkregen entitlementIds.
